# 实验14：通信优化消融实验总结

## 实验目的

前面的实验表明，单独把Linear放到FPGA会产生频繁的GPU-FPGA往返，通信时间可能超过FPGA节省的计算时间。本实验在同一组参考条件下，分别加入激活压缩、FFN子图融合驻留、共享映射一段拷贝和双缓冲，判断每种方法是否真正改善端到端延迟或多请求吞吐率。

所有结果都是无硬件条件下的敏感性结果，不能作为Jetson-FPGA真实性能预测。

## 建模方法

- 参考条件保持为FPGA Linear相对GPU快4倍、FPGA侧PCIe有效带宽4 GB/s、固定延迟20 us。
- 激活压缩测试2倍和4倍压缩。编解码采用每端2 us固定开销和50 GB/s处理带宽。
- 将每个Transformer Block中的`FFN1 + GELU + FFN2`合并成一个可驻留FPGA的子图任务。FPGA上的GELU暂时假设与GPU等速，三个算子只支付一次FPGA调度开销。
- 共享映射和直接DMA按一段物理数据移动建模，主机中转按两段数据移动建模。
- 双缓冲设置两个FPGA输入缓冲槽，允许下一请求的数据传输与当前请求的FPGA计算重叠。

## 单请求结果

| 方法 | 通信感知策略时间 | 相对GPU-only | FPGA Linear等价数 |
| --- | ---: | ---: | ---: |
| GPU-only/原始Linear基线 | 22.184 ms | 1.000x | 0 |
| 仅2倍压缩 | 22.184 ms | 1.000x | 0 |
| 仅4倍压缩 | 22.184 ms | 1.000x | 0 |
| FFN融合驻留 | 18.910 ms | 1.173x | 24 |
| 仅共享映射一段拷贝 | 22.184 ms | 1.000x | 0 |
| FFN融合 + 2倍压缩 | 17.299 ms | 1.282x | 24 |
| FFN融合 + 2倍压缩 + 一段拷贝 | 16.798 ms | 1.321x | 24 |

单独压缩或单独减少一次拷贝虽然降低了通信成本，但在参考条件下仍不足以让独立Linear卸载获利，因此通信感知策略继续选择GPU。FFN融合是本轮最关键的结构优化：它让12个FFN子图整体放到FPGA，中间的GELU不再导致`FPGA -> GPU -> FPGA`往返。融合后DAG从125个任务和148条边减少为101个任务和124条边。

在全部候选任务都放FPGA的诊断实验中，2倍压缩将时间从48.870 ms降至35.605 ms，4倍压缩降至26.455 ms，但仍慢于GPU-only；加入FFN融合、2倍压缩和一段拷贝后，全部卸载降至21.359 ms，才达到1.039倍条件加速。相比之下，通信感知选择性卸载只选择12个融合FFN岛，即24个Linear等价算子，达到16.798 ms，说明选择性卸载仍然更适合低延迟目标。

## 多请求与双缓冲结果

在8个请求同时到达时，组合优化使用单缓冲的通信感知吞吐率为101.065 requests/s，双缓冲提高到102.227 requests/s，相对GPU-only为2.268倍。提升只有约1.15%，因为延迟型策略只卸载12个融合FFN岛，流水线压力较小。

全部卸载在单缓冲下为73.742 requests/s，双缓冲提高到105.952 requests/s，提升约43.7%，相对GPU-only达到2.350倍。它的单请求时间21.359 ms，仍差于选择性卸载的16.798 ms。这说明低延迟和高吞吐是两个不同目标：低延迟策略应选择性卸载，高吞吐策略可以利用双缓冲和更多FPGA任务形成跨请求流水线。

## 当前结论

1. 只减少数据量不一定能改变卸载决策，减少GPU-FPGA切换次数更关键。
2. `FFN1 + GELU + FFN2`融合驻留是当前最有效的单项优化，说明系统设计不能只考虑单个Linear核。
3. 压缩和一段拷贝在融合基础上继续改善结果，组合优化的效果明显高于任一单项优化。
4. 双缓冲主要提高多请求吞吐率，不会改善单请求串行延迟。
5. 共享映射和直接DMA在相同带宽、延迟假设下结果相同，这只是当前抽象成本相同，不能说明真机机制等价。
6. 当前最好结果为条件结果：低延迟模式1.321倍，8请求吞吐模式2.350倍，均不能作为真实硬件性能结论。

## 局限与后续工作

SimGrid没有实现真实压缩算法、融合FPGA Kernel、缓存同步或DMA驱动。压缩对模型精度的影响也不在本实验范围内。当前编解码器按独立且不竞争的端点资源建模，双缓冲只限制FPGA输入缓冲，仍是简化模型。

下一步应在IRIS中准备两个自定义策略：面向单请求延迟的通信感知选择性卸载，以及面向多请求吞吐的缓冲和队列感知策略。硬件到位后需要测量压缩开销、FPGA融合FFN时间、共享映射同步成本、DMA可用性和真实计算通信重叠，再替换当前敏感性参数。
