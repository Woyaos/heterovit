# 单次推理 Tile 流式设计与当前状态

## 结论

当前项目原有的双缓冲只针对多个独立推理请求。本实验新增单次 ViT 推理内部的
FFN tile 流式模型。其依据是 FFN 对每个 token 独立执行相同的 FC1、GELU 和 FC2，
因此可以按 token 分块而不改变数学结果。Attention 会关联全部 token，仍作为跨层
同步点，本实验不假设十二个 Transformer Block 可以任意并行。

## 候选硬件结构

一个融合 FFN 被划分为输入传输、FC1、GELU、FC2 和输出传输五类阶段。输入、两个
扩张中间结果和输出分别设置有限数量的缓冲槽。双缓冲时，tile k 在 FC1 中计算的同时，
tile k+1 可以进入另一个输入槽；FC1、GELU 和 FC2 若由独立硬件进程实现，还可以让
不同 tile 同时处在三个计算阶段。

该结构有两个不同实现等级：

1. 整张量 DMA + FPGA 内部 tile 数据流。PCIe 仍只传输完整输入和输出，tile 只用于
   FPGA 内部 FC1/GELU/FC2 重叠。这一方案对驱动要求较低，应作为首要后备方案。
2. 端到端 tile 流。DMA 在同一个传输描述符下持续产生或接收 tile，FPGA收到部分输入
   后即可开始计算。这一方案可能进一步降低单请求延迟，但必须由DMA IP和驱动支持。

不能为每个小 tile 单独提交一次 PCIe DMA。模型显示固定启动开销会迅速抵消流水收益。

## 当前敏感性结果

模型首先复现现有完整 FFN 区间 638.300 us。默认使用FP16激活、两个2-bit权重矩阵，
2-bit是因为三值 `-1/0/+1` 至少需要三个编码状态。以16-token、双缓冲、独立FC1和FC2
计算进程、流式DMA描述符为初始HLS候选，条件性FFN时间为282.370 us，保守激活缓冲
约480 KiB，两个低比特权重约1152 KiB。把这一条件性结果代入十二个FFN后，整模型
敏感性时间约13.579 ms。

这些数字不是RF880预测。当前模型还没有HLS给出的启动间隔、时钟、资源占用、FIFO
停顿和DDR竞争。极小tile得到的更低时间只是零控制开销下界，不能称为工程最优点。

## 真实实现的准入条件

- FC1、GELU和FC2必须能够作为并发数据流进程综合，或明确退回共享计算引擎模型。
- C/RTL协同仿真必须证明FIFO/PIPO深度不会死锁，输出与未分块实现数值一致。
- 实现后频率以及LUT、FF、BRAM、URAM、DSP占用必须在RF880其余逻辑预留后可接受。
- 两个低比特权重应驻留片上或明确计入PL DDR读取时间。
- DMA测试必须区分“每tile一次提交”和“一个描述符持续流式传输”。
- 时间线必须证明输入DMA、三个计算阶段和输出DMA确实重叠。
- 最后使用Jetson GPU-only、完整FFN非流式、内部流式和端到端流式进行单请求消融。

## 论文中的准确表述

现在可以写“提出并实现了单请求FFN tile数据流的资源约束模型，并完成了tile尺寸、
缓冲数量、DMA提交方式和计算引擎复制方式的设计空间分析”。在HLS和硬件测试完成前，
不能写“已在RF880实现tile流水”或使用13.579 ms作为真实加速结果。
