# RF880 + Jetson 异构推理接口约定（待实测确认）

## 当前模型与两种内核能力

当前 ONNX 被识别为 ViT-Base/16-like，批量 1、197 个 token、隐藏维度 768。一个 FFN 的 `fc1` 输入/输出分别为 `[1,197,768]`、`[1,197,3072]`；GELU 输入/输出均为 `[1,197,3072]`；`fc2` 再输出 `[1,197,768]`。按当前 FP16 激活假设，三种激活大小分别为 302592、1210368、302592 字节。实际部署精度、内存布局、对齐、量化/反量化格式必须由模型和 FPGA 开发人员共同确认。

**能力 A：只提供单个低比特 Linear 内核。** 调度器只能把 `fc1` 或 `fc2` 作为单任务 FPGA 候选；若 GELU 在 GPU，两个 Linear 之间的 1210368 字节中间激活须往返传输，且存在两次独立内核派发。当前“完整 FFN 17.994 ms”仿真不适用，应将 `supported_fpga_blocks` 置空重新求解。

**能力 B：提供完整 `fc1+GELU+fc2` 内核或等效片上数据通路。** 入口与出口激活各跨一次设备边界，中间激活留在 FPGA 侧；仿真中的完整 FFN 候选才有工程对应物。必须确认 GELU 的数值定义、权重/偏置和尺度处理、两个 Linear 之间的缓存位置及容量，以及该子图是否真的只需一次派发。当前能力表只是能力 B 的假设，尚非 RF880 实现。

## 运行时最小交接项

1. 为每个 FPGA 候选给出内核名称、输入输出数据类型与布局、权重编码及常驻策略、缓冲地址/对齐、最大 token/hidden 形状、一次任务的派发/完成接口，以及多请求并发限制。
2. 确认板上 PCIe 协商代际和 x4 宽度、RF880 端点驱动和 DMA IP、Jetson GPU-主存拷贝、主存-FPGA 双向 DMA 的真实路径。当前模型使用主机中转两段；共享映射或直接 GPU-FPGA DMA 只有在驱动、地址映射和一致性联合测试通过后才可启用。
3. 单缓冲至少定义“传输占用->FPGA 计算->释放”的状态；双缓冲须分别给出缓冲数量、容量、同步机制与是否允许传输/计算并行。SimGrid 中的 semaphore 是**模型**，不是板上双缓冲实现。
4. 对一个请求分别记录 GPU 算子、GPU-主存拷贝、主存-FPGA DMA、FPGA 内核/派发、返回拷贝和同步的开始/结束时间；统一时间戳或做时钟校准，避免把排队时间漏算或重复算。
5. 每个方向用多个负载大小拟合 `T(S)=alpha+S/B`，再用未参与拟合的大小检验误差；测量阶段包含固定派发/同步与是否可重叠。校准后给出所有能力表和配置文件中的**实测来源、日期、条件**。
6. 用同一 ONNX、输入、精度目标与批量，对照真实 GPU-only 和异构输出的数值误差与任务结果；端到端实验需预热、重复多轮，报告中位数、p95、方差/置信区间、吞吐与模型预测误差。低比特权重精度本身由量化工作负责，但部署需要验证格式转换和跨设备输出一致性。

## IRIS 交接边界

DP 已导出 101 任务、124 依赖的计划清单，其中 12 个 FFN 子图指定 FPGA。IRIS 自定义策略现可读取固定设备字段，计划版骨架能编译；目标设备缺失时严格计划不会静默改到 GPU。当前默认 CPU-only 运行的 `hetero_noop` **不**执行真实 ViT，也不证明 GPU/FPGA 内核名称、架构枚举、内存对象或 DMA 路径可用。上板后须替换空内核，接入 CUDA/FPGA 实现和真实 `iris_mem`，再测试计划设备确实被执行。
