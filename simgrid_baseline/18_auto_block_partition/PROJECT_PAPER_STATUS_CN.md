# GPU-FPGA 异构 ViT 部署：截至 2026-09-15 的论文工作总报告

## 1. 研究问题与写作边界

本课题负责**异构部署如何降低端到端推理延迟**，不负责低比特量化算法或 FPGA 计算内核本身。目标设备是 Jetson AGX CPU/GPU + RF880 FPGA，经板级 PCIe x4 相连；Jetson 型号、PCIe 实际代际/带宽和 DMA 路径待上板确认。当前 `vit.onnx` 检查为 **ViT-Base/16-like**：12 个 Transformer 块、768 隐藏维度、约 8645 万参数；论文中不要未经复核写成 ViT-Small。

论文应说“现有 GPU 低比特实现的实际收益可能被数据格式转换、非矩阵算子和异构边界传输抵消”，**不能说 GPU 从原理上不能执行 -1/0/1 运算**。前者必须用最终目标平台的逐算子和端到端测量证明。EQ-ViT 的写作链条是实际瓶颈测量、模型/设计、板上结果及模型预测误差，而不是先假定加速再展示仿真；本项目目前只完成其中的**方法与假设参数仿真**。[EQ-ViT 原论文](https://peipeizhou-eecs.github.io/publication/2024_esweek_eqvit/2024_esweek_eqvit.pdf)

| --- | --- | --- |

| 初步瓶颈假设 | 比较逐 Linear 跨设备卸载造成的 97 条跨设备边、194 段主机中转传输；默认模型时间 35.591 ms，劣于 GPU-only 24.749 ms | 假设参数下的模型结果 |
| 成本形式化 | 计算+派发+编解码+每段 `alpha+bytes/B`；完整 DAG 再考虑 GPU、FPGA、链路占用 | 代码模型及单元测试，未校准 |
| 合法子图与决策 | 只融合无额外消费者/输入、GPU 入口出口固定的 FFN；能力表筛掉无内核/缓冲的候选；串行区域 DP 选块与设备 | DP 对穷举测试，区域内最优 |
| 全模型验证 | 缩约被选的 FFN，保留所有外部边；固定部署解析重放，另以 SimGrid Actor/Link/Semaphore 事件仿真 | 轨迹/依赖审查通过，仍为敏感性仿真 |
| 运行时交接 | IRIS 已有 101 任务/124 依赖的控制骨架；加入 9 字段计划设备清单，导出 12 个 FPGA 子图，计划版骨架编译 | CPU-only 空计算提交；计划设备未执行 |

HEFT 的“比较异构设备预计完成时间”是已有经典调度思想，不能作为本研究的新算法单独申明。我们的可写方法重点是：**ViT 依赖合法性 + 内核能力约束 + 跨设备往返传输共同决定卸载粒度；串行 FFN 精确划分与全 DAG 资源重放分开验证**。[HEFT 原论文](https://doi.org/10.1109/71.993206)

此前项目阶段也已建立基础：从 SimGrid 单机任务/两设备流水入门，检查共享链路争用；抽取 ONNX 工作负载和逐任务成本输入格式；比较 GPU-only、静态 FPGA 卸载与算子级 EFT；做 FFN 融合、激活压缩、共享映射、直接 DMA 的设计空间/消融，以及动态负载和积压阈值实验；根据 RF880+AGX 文档固定板级拓扑、生成 GPU/FPGA 算子与传输测量模板；在 IRIS 添加成本策略与 ViT DAG 空计算骨架。这些阶段建立了**工具链和候选机制**，不等于压缩、共享映射、直接 DMA 或动态模式切换已在真实板上实现。尤其早期通用配置的 SimGrid 轨迹、后期 RF880 配置的解析回退与本轮 RF880 事件重放是不同证据等级，不应合并成同一实测结论。

## 3. 理论支撑与严格适用范围

对入口/出口都固定在 GPU、内部无外部依赖的 FFN 链，若候选块 `[i,j)` 可由设备 `d` 执行，则局部目标为块计算时间之和，加上**相邻块设备不同**时的边传输时间，以及 GPU 入口/出口的往返时间。动态规划状态 `F(j,d)` 表示前 `j` 个算子以设备 `d` 结束的最小链成本；转移枚举前一块终点和设备。由于链没有分支、成本按块/边可加，最优解的前缀也最优，因此 DP 对**被认证的区域目标**是精确的。测试在多种 FPGA 速度、PCIe 延迟、完整 FFN 内核是否可用的组合下与独立穷举一致。

这个证明**不延伸到整个有残差分支、共享链路排队和多请求并发的 ViT DAG**。全模型解析重放和 SimGrid 只用于评价已选计划，而不是证明全局最优。通信门限同样是条件结论：默认假设下单 FFN GPU 1213.212 us，完整 FPGA 计算 332.748 us、往返 305.552 us，净收益 574.913 us；按 4 倍 Linear 加速和 3.2 GB/s 带宽，主存-FPGA 固定延迟约 312.5 us/方向时局部决策切换。若 GELU 不能驻留 FPGA、权重/缓冲不足、需要额外量化转换，门限和结果必须重算。

SimGrid 的 Actor、Link 和同步对象能表达资源争用，但它**不是硬件测量工具**：执行时间和带宽仍需输入。SimGrid 文档建议用简单的 Raw 网络模型表示 PCI 类总线；本机 SimGrid 3.35 没有 Raw，只能使用 CM02，因此网络语义和真实 PCIe 的一致性尚待校准。[SimGrid S4U 文档](https://simgrid.org/doc/latest/app_s4u.html)、[SimGrid 网络模型文档](https://simgrid.org/doc/latest/Models.html)

## 4. 当前数据支持：必须标注为“假设参数下的仿真”

### 单请求及调度策略

| 方案 | 解析全 DAG 时间 | SimGrid 事件时间 | 当前结论 |
| --- | ---: | ---: | --- |
| GPU-only | 24.749 ms | 24.749 ms | 同模型基线，非 TensorRT 实测 |
| 逐个 Linear 固定上 FPGA | 35.591 ms | **36.741 ms** | 在当前参数下单请求跨设备边界过多 |
| 算子级通信 EFT | 24.749 ms | 本轮未重放 | 当前原 DAG 选择全 GPU |
| 固定 12 个完整 FFN 上 FPGA | 17.850 ms | 本轮未单独重放 | 在默认均匀参数下与自动计划相同 |
| 自动 FFN 区域 DP | 17.850 ms | **17.994 ms** | 比 GPU-only 事件时间低约 27.3%；比固定 FFN **无已证明提升** |

事件时间与解析时间相差约 0.144 ms，说明资源事件顺序应单独检查；不能称此差值为“相对真实硬件的预测误差”。默认 12 个 FFN 形状/成本一致，自动策略全选；60 组 FPGA 速度、PCIe 固定延迟和带宽扫描中，30 组全选、30 组退回 GPU，没有中间层数。人工把第一层 FFN 的三个 GPU 任务各设为 100 us 时自动只选 11 个，17.512 ms 优于固定 12 个的 17.669 ms；**这是人工机制测试，不是性能论文结果**。

## 5. 旧实验清理：哪些数据不宜作为核心论文证据

旧 RF880 总结文件中的 `simgrid_makespan_us` 字段实际上标记为 `analytical_fallback_no_simgrid`；旧“单缓冲/双缓冲”行在相同方案、请求数下完全相同，旧在线 p95 也是解析排队公式而非逐请求事件记录。新实验已用真实 SimGrid 事件重放代替**默认 FFN 计划**的并发/在线部分；旧压缩、共享映射、直接 DMA 场景仍只是设计空间的上界或敏感性设想，特别是直接 DMA 和完整 FFN/GELU 内核未获板上验证。旧数值不能和新事件重放混成同一实验表。

此前周报把 [OSDI 2022 Han 论文](https://www.usenix.org/conference/osdi22/presentation/han) 作为“DAG/FFN 融合的理论依据”不准确：该论文研究并发 GPU 推理的微秒级抢占。任务依赖的形式化依据应由实际 ONNX DAG 和本项目的区域合法性证明给出；异构完成时间思想可引 HEFT，而不是引用不相关论文。

## 6. IRIS 与真实硬件可行性

IRIS 是运行时执行/设备选择框架，**不会因为知道 FPGA 型号就自动产生 FPGA 内核或模拟算力**。现有 IRIS 骨架可生成任务与依赖、读取成本元数据和固定 DP 设备字段。默认自动清单在 CPU-only OpenMP `hetero_noop` 上提交 101 任务、124 依赖成功，成本模型单测通过；计划清单逐项对上 DP，12 个任务标记 FPGA，计划版程序编译通过。它**没有**真实 `iris_mem` 数据流、CUDA/FPGA ViT 内核、PCIe DMA 和目标设备架构联合测试。

完整 FFN 加速方案的可行性取决于 RF880 能否在 FPGA 侧连续处理 `fc1+GELU+fc2` 并留住 1.210 MB 中间激活；只提供两个 Linear 时必须重新建模。Jetson 侧主机中转路径原则上可通过 DMA/缓冲设计实现，但有效带宽、同步时间、地址一致性和双缓冲并行程度不能由原理图推定。交接规格详见 [RF880 运行时接口约定](FPGA_RUNTIME_CONTRACT_CN.md)。

## 7. 论文应如何写，尚缺什么

当前能正式写成**方法章节和仿真章节**的：任务图/合法 FFN 区域、分项开销模型、能力约束、链 DP 的适用条件与证明、全 DAG/SimGrid 评价流程、默认/敏感性/并发/在线对照，并把所有数值标注为“assumed sensitivity profile”。可以提出“通信感知、子图粒度的部署方法”作为待硬件验证的研究主张；**不能**把融合、双缓冲、共享映射、直接 DMA 说成全部已上板实现，也不能宣称超过固定 FFN 方案的默认性能。

若想达到 EQ-ViT 那样的完整证据链，还缺：真实 Jetson GPU-only（同模型/精度的 TensorRT 或等效基线）逐算子与端到端剖析；RF880 单 Linear/完整 FFN 内核、缓冲与权重驻留的实际能力；多尺寸双向 PCIe/主存拷贝与派发实测；量化/格式转换和输出精度一致性；实测参数校准后用**留出样本**比较模拟与板上时间的预测误差；单请求中位数/p95、稳态吞吐、负载/SLO、消融及资源/功耗（若主张）。论文创新是否足够强，最终取决于这些实测是否支持“异构方案胜过强 GPU 基线”，而不是方法数量。EQ-ViT 自身报告了板上实测与模型预测对照，这一点目前本项目尚未做到。[EQ-ViT 原论文](https://peipeizhou-eecs.github.io/publication/2024_esweek_eqvit/2024_esweek_eqvit.pdf)

本阶段明确结论：**无需硬件的结构抽取、决策实现、精确性测试、事件仿真、在线场景和 IRIS 计划接口已完成；真实加速结论、模型准确率、内核/传输功能验证必须等待板卡。**

论文贡献表述建议分为三项：**已实现的方法**是能力/依赖认证的 FFN 子图划分和统一计算通信记账；**已验证的仿真系统**是解析与 SimGrid 两级重放、负载及缓冲敏感性、IRIS 固定清单导出；**待完成的实证贡献**是按 RF880+AGX 实测校准并证明端到端延迟/吞吐优于强 GPU-only 基线。第三项未完成之前，不宜在摘要中宣称实际硬件加速或高精度预测模型。
